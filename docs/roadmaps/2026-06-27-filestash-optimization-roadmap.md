# SideStash 优化路线图

更新时间：2026-06-27

## 1. 当前基线

截至目前，SideStash 已经完成了这一轮最关键的交互基础：

- 菜单栏面板可从 Finder 窗口边缘滑出并贴附在窗口侧边
- 面板高度可与 Finder 窗口高度对齐
- 当面板附着在某个 Finder 窗口时，可跟随该窗口移动并在该窗口关闭时同步关闭
- 在没有辅助功能权限时，仍可通过 `CGWindow` 路径获取 Finder 窗口几何信息
- 应用图标已从通用 SF Symbol 升级为更贴近产品语义的自绘图标

这意味着项目已经从“概念验证”阶段进入“稳定化和产品化”阶段。后续优化不应再以新增视觉效果为主，而应优先提升 Finder 集成稳定性、拖拽手感、数据可靠性和日常可用性。

## 2. 路线图目标

后续优化围绕四个目标展开：

1. 让 Finder 集成足够稳定，避免边界场景下出现跳窗、错附着或关闭不同步
2. 让拖入、拖出、吸附、关闭这些核心交互更接近系统级体验
3. 让 stash 数据层更可靠、更可测试，并为后续功能扩展留出余量
4. 在不破坏“轻量、即时、菜单栏工具”定位的前提下，逐步补齐高价值产品能力

## 3. 优先级分层

### P0：必须优先完成

这些项直接影响当前体验稳定性，建议优先做。

#### 3.1 Finder 窗口身份统一

当前 Finder 窗口追踪仍然分为 `AX` 与 `CGWindow` 两条路径，虽然功能已可用，但窗口身份模型尚未完全统一。

建议动作：

- 为 `FinderWindowTracker` 引入统一的窗口快照模型
- 将 `AX` 路径与 `CGWindow` 路径都收敛到同一份 `windowID + rect + source` 数据结构
- 明确“附着目标窗口”与“当前 Finder 活跃窗口”的区别
- 减少面板在多 Finder 窗口场景下错误切换附着目标的可能性

完成标准：

- 打开多个 Finder 窗口时，SideStash 始终跟随最初附着的那一扇
- 目标 Finder 窗口关闭后，SideStash 不会跳到其他 Finder 窗口上
- 目标 Finder 窗口移动、缩放、前后台切换时，SideStash 行为一致

#### 3.2 窗口生命周期抛光

目前“Finder 关闭则面板关闭、用户手动关闭”已经具备，但生命周期行为还可以更系统化。

建议动作：

- 定义 Finder 最小化、隐藏、切换 Space、全屏切换时的面板策略
- 明确点击外部区域后是否关闭
- 支持 `Esc` 关闭
- 防止关闭动作和重新触发 drag detector 之间出现短时间误触发

完成标准：

- 用户能预测面板何时保留、何时隐藏、何时关闭
- 不会出现刚关闭又立刻被重新拉起的情况

#### 3.3 测试与可维护性加固

当前最值得补强的工程面是测试边界和共享状态隔离。

建议动作：

- 继续减少对 `StashStore.shared` 的直接依赖
- 为 stash 目录、metadata、拖出恢复流程增加更独立的测试夹具
- 为窗口跟随、关闭同步、Finder 多窗口匹配增加单元测试
- 将当前已证明有效的几何和窗口快照逻辑继续模块化

完成标准：

- 关键交互链路具备稳定回归测试
- 新功能不会频繁因为共享状态污染而误报失败

### P1：高价值的交互与产品优化

这些项不会阻塞当前功能，但会明显提升完成度和可用性。

#### 3.4 拖拽反馈与吸附手感

建议动作：

- 增加“即将吸附到 Finder 边缘”的预反馈
- 调整滑出、回收、吸附时的动画曲线和透明度变化
- 在 drag in 与 drop zone 命中时增加轻量视觉反馈
- 优化 drag out 时文件卡片的反馈状态

目标效果：

- 交互更像系统工具，而不是普通悬浮窗

#### 3.5 文件列表体验

建议动作：

- 增加排序方式，如最近放入、名称、类型
- 增加搜索
- 增加置顶或固定条目
- 增加快速预览入口
- 增加“一键恢复到原位置”

目标效果：

- 面板从“临时放一下”升级为“临时但高频可管理”

#### 3.6 数据刷新与性能

建议动作：

- 减少全量 `refreshItems()` 的频率
- 引入更细粒度的数据刷新策略
- 对大文件夹和大量 stash 条目做图标加载优化
- 考虑文件系统变化监听，而不是完全依赖手动刷新

目标效果：

- stash 项增多后，面板仍然保持轻快

### P2：中长期演进方向

这些项适合在核心稳定后择机推进。

#### 3.7 自动整理能力

建议动作：

- 自动过期清理
- 根据时间或容量阈值提醒清理
- 最近恢复历史
- 恢复失败时提供重试或手动定位入口

#### 3.8 可配置能力

建议动作：

- 面板宽度或视觉样式偏好
- 自动关闭策略
- 吸附位置偏好
- 快捷键呼出

#### 3.9 发布与分发准备

建议动作：

- 明确权限说明文案
- 增加首次使用引导
- 检查签名、打包、分发与升级流程
- 补齐本地化和无障碍文案

## 4. 建议执行顺序

建议按四个阶段推进，而不是按零散任务穿插。

### 阶段 A：稳定化

目标：先把 Finder 集成这条主链路做扎实。

范围：

- Finder 窗口身份统一
- 生命周期策略补齐
- 关键测试补强

预期结果：

- 面板行为在多窗口、切换、关闭等场景下可预测

### 阶段 B：交互抛光

目标：提升“像系统功能”的感觉。

范围：

- 动画曲线
- 边缘吸附反馈
- drop 反馈
- 手动关闭与快捷关闭体验

预期结果：

- 用户不需要思考，拖拽与关闭都更顺手

### 阶段 C：列表与数据体验

目标：让 stash 在文件增多后仍然可用。

范围：

- 搜索
- 排序
- 置顶
- 快速预览
- 增量刷新

预期结果：

- 面板从 demo 型工具变成日常可依赖工具

### 阶段 D：产品化与发布准备

目标：降低首次使用门槛，提升长期维护能力。

范围：

- 首次引导
- 权限说明
- 本地化与无障碍
- 打包、签名、发布准备

预期结果：

- 可以更安心地给其他人使用或继续公开演进

## 5. 近期建议的三件事

如果只看最近一到两轮迭代，我建议优先做这三件事：

1. Finder 窗口身份统一
   这是当前最关键的稳定性工程。

2. 生命周期策略补齐
   把最小化、隐藏、外部点击、`Esc` 关闭这些规则明确下来。

3. 测试隔离与共享状态去耦
   这是后续持续迭代的地基。

## 6. 暂不建议优先推进的事项

以下方向不是没价值，而是不建议现在排在前面：

- 大规模视觉重做
- 复杂设置页
- 云同步或跨设备能力
- 与 Finder 以外应用的深度联动
- 过早引入大量偏好项

原因很简单：当前最值钱的提升仍然在“稳定性”和“像系统工具一样可靠”。

## 7. 结论

SideStash 当前最正确的方向，不是立刻继续叠功能，而是先把已经非常有潜力的 Finder 附着式交互打磨成稳定、可预测、轻量的系统级体验。

一条简化后的判断标准可以是：

- 先稳住窗口与拖拽主链路
- 再补交互反馈
- 然后做列表管理能力
- 最后补发布与长期演进能力

如果后续继续按这个顺序推进，SideStash 会更像一个成熟的 macOS 小工具，而不是一个只在演示里好看的概念原型。
